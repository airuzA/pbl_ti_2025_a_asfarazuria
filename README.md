# PWL Sample

A minimal native PHP MVC skeleton — used for teaching Advanced Web Programming. No framework (Laravel, CodeIgniter, etc.) — routing, controllers, models, and views are all written by hand.

## Requirements

- PHP 8.1+
- Composer
- MySQL

## Setup

```bash
composer install
```

Create the database (empty — tables get created later as you generate resources):

```sql
CREATE DATABASE tik_pbl;
```

Adjust the credentials in `config/database.php` if they differ from the default (`root` / no password / `localhost`).

## Running

```bash
composer serve
```

Open `http://localhost:5000`.

## Generating a new resource

This project ships with no resources at all (no Products/Categories/etc.) — it's empty, ready to generate whatever you need:

```bash
composer makeMVC ResourceName
```

Example:

```bash
composer makeMVC Categories
```

This creates:

```
models/CategoriesModel.php
controllers/Categories.php
views/categories/index.php
views/categories/form.php
```

It's a minimal template (just an `id` + `name` field). The generator prints the `CREATE TABLE` query at the end — you still have to run that yourself. If the resource needs more fields, just edit the generated files directly.

To add it to the sidebar, edit `views/layout/header.php`.

## Folder structure

```
index.php              front controller -- EVERY request goes through here
config/database.php     PDO connection
core/Loader.php          helper for loading views from a controller
controllers/             one class per resource
models/                  one class per resource, talks to the database
views/
  layout/                header.php & footer.php, shared by every page
  errors/                error page (unhandled exceptions)
  <resource>/             index.php & form.php per resource
tools/make-mvc.php       generator behind composer makeMVC
docs/                    learning material, numbered 01 - 08
```

## Routing convention

The URL `/resource-name/{id?}/{action?}` gets translated by `index.php` into:

```
$controllerName->$action($id)
```

- `GET  /categories`              -> `Categories::index()`
- `GET  /categories/create`       -> `Categories::create()`
- `POST /categories/store`        -> `Categories::store()`
- `GET  /categories/{id}/edit`    -> `Categories::edit($id)`
- `POST /categories/{id}/update`  -> `Categories::update($id)`
- `POST /categories/{id}/delete`  -> `Categories::delete($id)`

`store`, `update`, and `delete` must go through POST — accessing them via GET returns 404.

If the URL has no third segment (e.g. just `/categories/{id}`), the default action is `detail`. Controllers generated by `composer makeMVC` don't get a `detail()` method automatically — add it yourself if you need it (`public function detail($id) { ... }`), otherwise that URL pattern will just 404.
